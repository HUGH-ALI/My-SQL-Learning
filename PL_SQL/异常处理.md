一、异常是什么    
 
PL/SQL 程序运行出错 → 抛出异常，异常处理器捕获错误、做处理，不让程序直接崩溃退出。
一共分3大类：  
 
1. 预定义异常：Oracle系统自带，对应常见错误（ NO_DATA_FOUND 、 TOO_MANY_ROWS 、 ZERO_DIVIDE 等），不用自己声明。  
2. 非预定义异常：Oracle内置错误，但没有现成异常名，需要自己绑定错误号。  
3. 用户自定义异常：业务上自己规定的错误（比如工资不能超过6000），系统不认，需要手动 RAISE 抛出。  
 
表格里常考的几个预定义异常：  
 
-  NO_DATA_FOUND ：SELECT INTO 查不到数据   ORA-01403  
-  TOO_MANY_ROWS ：SELECT INTO 返回多行   ORA-01422  
-  ZERO_DIVIDE ：除零  
-  DUP_VAL_ON_INDEX ：主键/唯一索引重复  
 
二、异常处理三步流程  
 
1. 声明：在 DECLARE 块里定义异常（预定义异常不用声明；另外两种要）  
2. 抛出：  
- 预定义、非预定义：出错时系统自动抛出  
- 用户自定义异常：必须手动写  RAISE 异常名;   
3. 捕获处理： EXCEPTION  段，用 WHEN 匹配异常，写处理代码  
 
语法模板  
 
DECLARE  

-- 这里声明异常  
  e_exception EXCEPTION;  
-- 声明完绑定错误号（PRAGMA 紧跟在它下面！）  
  PRAGMA EXCEPTION_INIT   (e_exception,-#####）;  
(注意：Oracle内部错误号用一个负的5位数表示  ，如-02292。其中-20999~-20000为用户定义错误的保留号)  

BEGIN  
  -- 正常业务代码  
EXCEPTION  
  WHEN 异常1 THEN  
    -- 处理代码  
  WHEN 异常2 THEN  
    -- 处理代码  
  WHEN OTHERS THEN   -- 兜底，放最后！捕获所有没匹配到的异常  
    -- 通用处理  
END;  
 
 
✅ 要点：  
 
- 一个 WHEN 可以用 OR 同时捕获多个异常   
- 一个异常只能被第一个匹配到的WHEN捕获并处理  
-  WHEN OTHERS 必须写在所有WHEN的最后面  

 【例9-21】查询姓为“Smith”的员工工资，如果该员工不存在，则输出“There is not such  
an employee!”；如果存在多个同名的员工，则输出其员工号、姓名和工资。  
DECLARE  
v_sal employees.salary%type;  
BEGIN  
SELECT salary INTO v_sal FROM employees   WHERE last name='Smith';  
DBMS OUTPUT.PUT LINE(v_sal);  
EXCEPTION  
WHEN NO DATA FOUND THEN  
      DBMS OUTPUT.PUT LINE('There is not such an emplyee!');  
WHEN TOO MANY ROWS THEN  
      FOR v_emp IN (SELECT * FROM employees WHERE last_name='Smith')             
LOOP  
     DBMS OUTPUT.PUT  
LINE(v_emp.employee_id || ' ' || v_emp.first_name || ' ' || v_emp.last_name || ' ' || v_emp. salary);  
END LOOP;  
END;  

【例9-22】删除 departments表中部门号为50的部门信息，如果不能删除则输出“There
are subrecords in employees table!"  

DECLARE  
e_deptno fk EXCEPTION;  
PRAGMA EXCEPTION_INIT(e_deptno_fk,-2292);  

BEGIN  
   DELETE FROM departments WHERE department_id=50;  
EXCEPTION  
   WHEN e_deptno_fk THEN  
   DBMS OUTPUT.PUT LINE(' There are subrecords in employees table!');
END;  



三、三种异常  
 
1. 预定义异常（例9-21）  
 

DECLARE  
  v_sal employees.salary%type;  
BEGIN  
  SELECT salary INTO v_sal FROM employees WHERE last_name='Smith';  
  DBMS_OUTPUT.PUT_LINE(v_sal);  
EXCEPTION  
  WHEN NO_DATA_FOUND THEN  
    DBMS_OUTPUT.PUT_LINE('There is not such an employee!');  
  WHEN TOO_MANY_ROWS THEN  
    -- 查到多条，循环输出
    FOR v_emp IN (SELECT * FROM employees WHERE last_name='Smith')  
 LOOP  
      DBMS_OUTPUT.PUT_LINE(v_emp.employee_id||' '||v_emp.last_name||' '||v_emp.salary);  
    END LOOP;  
END;  
 
 
解释：  
 SELECT INTO  要求只能返回一行：  
 
- 没数据 → 触发 NO_DATA_FOUND   
- 多条数据 → 触发 TOO_MANY_ROWS   
 
2. 非预定义异常（例9-22）  
 
这种Oracle错误有ORA编号，但是没有现成异常名字，需要两步绑定：  
 
DECLARE  
  e_deptno_fk EXCEPTION; --① 先定义异常变量  
  PRAGMA EXCEPTION_INIT(e_deptno_fk, -2292); --② 绑定错误号-2292（外键约束，有子记录不能删）  
BEGIN  
  DELETE FROM departments WHERE department_id=50;  
EXCEPTION  
  WHEN e_deptno_fk THEN  
    DBMS_OUTPUT.PUT_LINE('There are subrecords in employees table!');  
END;  
 
 
 PRAGMA EXCEPTION_INIT(异常名, 错误号)  是编译指令，把异常名和ORA错误号绑定。  
  
3. 用户自定义异常（例9-23）  
 
业务规则，数据库本身不认为是错，我们自己判定错误、手动抛出：  
 
【例9-23】修改108号员工的工资，保证修改后工资不超过6000元。   
DECLARE  
e_highlimit EXCEPTION;  
v_sal employees.salary%TYPE;  
BEGIN  
   UPDATE employees SET salary=salary+100 WHERE employee_id=108
RETURNING salary INTO v_sal;  

IF v sal>6000   
THEN  
RAISE e highlimit;  
END IF;  

EXCEPTION  
WHEN e_highlimit THEN  
DBMS_OUTPUT.PUT_LINE('The salary is too large!');  
ROLLBACK;  
END;  

注意:  
①RETURNING 字段 INTO 变量   
配套 INSERT / UPDATE / DELETE 使用，作用：把刚刚修改之后的数据，拿出来存到变量里  
UPDATE employees SET salary=salary+100 WHERE employee_id=108
RETURNING salary INTO v_sal;  

②ROLLBACK  
1. UPDATE 执行完 → 修改已经在事务里生效了（内存里改好了，还没commit）  
2. 发现工资>6000 → RAISE抛出异常，跳到异常处理段  
3. 这里的业务规则：工资不能超过6000，这次加薪是不允许的，要撤销这次修改  
4.  ROLLBACK;  = 回滚事务，撤销刚才那条UPDATE  
 
重点：不写RAISE，这个异常永远不会触发。  
 
四、WHEN OTHERS  
虽然OTHERS异常处理器可以捕获各种异常，但并不返回相关错误信息，无法判断到底块有是哪个错误产生了异常，该错误是否有预定义的异常等。为此，PL/SOL提供了两个函数来获取错误的相关信息。  
 
WHEN OTHERS  兜底捕获所有没被前面WHEN接住的异常。  
配套两个函数，用来拿到错误信息：  
 
（1)SQLCODE：返回当前错误代码。如果是用户定义错误，则返回值为1；如果是
ORA-1403: NO DATA FOUND错误，则返回值为100；其他Oracle内部错误则返回相应的错误号。  
（2)SQLERRM：返回当前错误的消息文本。如果是Oracle内部错误，则返回系统内部的  
错误描述；如果是用户定义错误，则返回信息文本    “User-defined Exception”。  
-  SQLCODE ：错误编号  
- 用户自定义异常：返回 1   
- NO_DATA_FOUND：返回 100   
- 其他Oracle错误：返回对应负数ORA号  
-  SQLERRM ：错误文字描述  
 
【例9-24】利用 OTHERS异常处理器捕获异常，并说明错误的原因。  
DECLARE  
  v_sal employees.salary%TYPE;  
  e_highlimit EXCEPTION;  
  v_code NUMBER(6);  
  v_text VARCHAR2 (200)；  
 
BEGIN  
  SELECT salary INTO v_sal FROM
  employees WHERE last_name='Smith'  

  UPDATE employees SET  salary=salary+100 WHERE employee_ id=200：  

IF V_sal>6000   
THEN  
  RAISE e_highlimit;  
END IF;  

EXCEPTION  
   WHEN e_highlimit THEN  
     DBMS_OUTPUT.PUT_LINE('The salary is    too large!');  
   ROLLBACK;  
  WHEN OTHERS THEN  
 v_code:=SQLCODE;v_text:=SQLERRM;  

DBMS_OUTPUT.PUT_LINE(v_code||''||v_text);
END;  

 
五、异常传播  
 PL/SQL程序运行过程中出现错误后，根据错误产生的位置不同，其异常传播也不同。  

1. 执行部分抛出异常  
- 当前块有对应的WHEN处理器 → 本地处理，块结束  
- 当前块没有对应的WHEN处理器 → 异常往上抛给外层块，外层继续处理；没有外层就交给调用环境  

2. 声明段、异常处理段里面出错  
✅ 直接抛向外层，本块自己的EXCEPTION抓不到！  
 
由此可见，无论是执行部分的异常，还是声明部分或异常处理部分的异常，如果在本块中没有处理，最终都将向外层块中传播。因此，通常在程序最外层块的异常处理部分放置OTHERS异常处理器，以保证没有错误被漏掉检测，否则错误将传递到调用环境。
