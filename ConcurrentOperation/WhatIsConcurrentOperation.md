并发操作
 
定义：多个用户/多个事务，同时对同一个数据库的数据进行读写操作。
 
举个例子：
A同学在查课程剩余名额，B同学同时修改、扣减名额，这就是并发。
 
并发带来的3个经典问题
 
1. 丢失修改
两个事务同时读同一个数据，先后修改提交，后提交的覆盖前面的修改，前面的改动丢了。
 
例：A、B同时读库存10，A改成9提交，B改成9提交，本来应该变成8，结果变成9 → A的修改丢了。
 
2. 不可重复读
同一个事务内，两次读取同一批数据，中间别的事务修改并提交了，两次读到结果不一样。
3. 读脏数据（脏读）
一个事务读到了另一个事务还没提交、后面回滚撤销的数据。
 
例：B改了数据还没提交，A读到这个值；随后B回滚，这个数据作废，A读到的就是脏数据。
 
一句话区分
 
- 脏读：读到别人未提交的数据
- 不可重复读：自己同一事务，两次读不一样（别人提交更新了）
- 丢失修改：两个人同时改，一个更新被覆盖
 
解决手段：封锁机制（共享锁、排他锁）、事务隔离级别
 
封锁机制
 
定义：封锁是实现并发控制的一种技术。事务在对某个数据对象（表、行等）操作前，先向系统发出请求，对它加锁；加锁之后，这个数据对象就有了一定的访问限制，其他事务不能随便读取或者修改，直到本事务释放锁。
 
两种基础锁
 
1. 共享锁（S锁，读锁）
 
- 加锁场景：事务只是读数据
- 规则：多个事务可以同时加S锁（共享）；不能加排他锁
 
一句话：读读可以并行，有人加S锁，别人不能改。
 
2. 排他锁（X锁，写锁）
 
- 加锁场景：事务要修改、增删数据
- 规则：一旦加上X锁，其他事务既不能加S锁，也不能加X锁
 
一句话：写的时候独占，别人不能读、不能改。
 
锁的粒度
 
可以锁整张表、也可以锁一行记录（行锁）。
 
配套考点：活锁、死锁
 
- 活锁：一个事务一直等待，别的事务不断优先拿到锁，它一直轮不到。
- 死锁：事务A拿着锁等B的锁；事务B拿着锁等A的锁，互相卡住，谁都无法继续。
 
封锁机制是数据库并发控制的方法，事务操作数据前先申请加锁，限制其他事务对该数据的访问，以此防止并发操作带来的丢失修改、脏读、不可重复读问题；主要分为共享锁S和排他锁X。
 
锁是对表和数据加还是对操作事物加的?不应该对表加吗对表加了S锁，那么大家都只能读取，加了排他锁那么只有等表修改完后其他事物才能执行

锁是加在【数据对象】上（行 / 页 / 表），不是加在事务上！事务只是“拿着锁”的一方。

怎么申请锁
默认情况下，不用手动写语句申请S/X锁！数据库自动加锁
 
- SELECT 查询：自动尝试加共享锁S（Oracle读操作默认不加锁，这个是考试理论，和真实Oracle有区别，答卷按课本写）
- UPDATE / DELETE / INSERT：自动加排他锁X
 
课本考试：重点区分【自动隐式加锁】和【手动显式加锁】
 
1、手动申请共享锁（S锁，表级）
 
sql  
LOCK TABLE course IN SHARE MODE;
 
 
含义：给course表加共享锁
 
- 其他事务可以读这张表，不能修改
- 直到执行  COMMIT;  或者  ROLLBACK;  锁释放
 
2、手动申请排他锁（X锁，表级）
 
sql  
LOCK TABLE course IN EXCLUSIVE MODE;
 
 
含义：给course表加排他锁
 
- 别的事务不能读、不能改这张表
- 提交/回滚才释放
 
3、行级锁（没法单独LOCK语句指定行，一般写SELECT ... FOR UPDATE）
 
 FOR UPDATE  就是手动给查到的行 加行排他锁X（考试高频）
 
sql  
SELECT * FROM course WHERE cno='C01' FOR UPDATE;
 
 
- 只锁住  cno='C01'  这一行
- 其他行不受影响，别人可以正常读写别的行
- 提交之后锁释放
 
 
1. 隐式锁（自动）
- DML（增删改）：自动加X锁（行锁）
- 查询：课本理论自动S锁；真实Oracle读不加锁（读不阻塞读）
2. 显式锁（手动LOCK / FOR UPDATE）
-  LOCK TABLE ... SHARE MODE  表S锁
-  LOCK TABLE ... EXCLUSIVE MODE  表X锁
-  SELECT ... FOR UPDATE  行X锁
 
易错坑
 
 FOR UPDATE  申请的是排他锁，不是共享锁！
用来锁住这行，防止别人同时修改，典型场景：先查库存、再扣库存。
